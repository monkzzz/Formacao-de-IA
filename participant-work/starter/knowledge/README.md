# Reusable knowledge

Owner: the agent proposes and maintains findings; the participant may correct them.
Store explanations that prevent repeated investigation, rather than a session diary.

Use one Markdown note per finding with a descriptive name and these fields:

- Finding, scope, date and status (`verified`, `inference`, `obsolete`).
- Cause or rationale, supporting evidence links, versions and reproduction method.
- When it applies, when it does not, and a trigger for checking it again.
- Related decisions and any superseding note.

Promote an observation only after checking its support. Do not turn a one-environment
workaround into a universal rule. Keep stale notes with an obsolete label and a
replacement link. No technical findings from another project are preloaded here.

Use [evidence](../evidence/README.md) for what happened and
[decisions](../context/decisions.md) for choices made from it.
